Was ist Vibecoding?

Du erklärst das Ziel. Die KI baut eine erste Version.

Du

«Ich brauche einen Gruppengenerator, der auf dem Handy funktioniert.»

→
Coding-KI

Erstellt Dateien, verbindet Funktionen und zeigt dir eine erste nutzbare Version.

→
Du wieder

Öffnest, klickst, prüfst und sagst konkret, was besser werden soll.

Ganz einfach:

Vibecoding bedeutet: Du beschreibst Software in normaler Sprache. Eine KI erzeugt den Code. Gemeinsam verbessert ihr das Ergebnis in mehreren Runden.

Etwas genauer erklärt

Der Begriff wurde 2025 von Andrej Karpathy geprägt. Heute wird er für eine Arbeitsweise verwendet, bei der eine KI viel Code erzeugt und der Mensch vor allem Ziel, Kontext, Entscheidungen und Prüfung übernimmt.

Quelle: IBM ↗

Der wichtigste Ablauf

Vibecoding ist ein Kreislauf, kein Zauberknopf.

Tippe die vier Stationen an. Nach jeder Runde wird die Lösung passender.

Drehrichtung01 → 02 → 03 → 04

Tippe auf «Nächste Station» oder direkt auf einen Kreis. Die Erklärung öffnet sich gross über dem Kreislauf.

Prompt-Werkstatt

Ein Prompt ist einfach dein Auftrag an die KI. Drei Entscheidungen reichen für einen guten Start.

Echte Beispiele

        
Vier Menschen, vier konkrete Probleme, vier echte Werkzeuge.

        
Öffne ein Beispiel. Die Zahlen stammen aus veröffentlichten Fallstudien der jeweiligen Plattformanbieter und sind keine Erfolgsgarantie.

        

          
          
          
          
        

        
Was alle Beispiele gemeinsam haben:Sie lösen ein konkretes Problem für eine klar beschriebene Gruppe. Genau damit solltest du ebenfalls beginnen.

      

    


    

      

        
Der Sicherheitscheck

        
Schnell bauen heisst trotzdem: denken, prüfen, schützen.

        
Entscheide bei jeder Situation. Du erhältst sofort eine Erklärung.

        

          
1. Darf ich Noten und Lernendendaten in einen öffentlichen Test laden?

          
2. Soll ich vor grossen Änderungen eine funktionierende Version sichern?

          
3. Muss ich Links, Eingaben, Uploads und Löschen selbst testen?

        

        Warum Prüfen wichtig bleibt: GitHub-Dokumentation ↗
      

    


    

      

        
Dein persönlicher Start

        
Deine erste kleine Version ist nur einen Prompt entfernt.

        
Du musst weder Code kennen noch alles im Voraus planen. Kopiere den Auftrag, warte auf die erste Version und klicke dich durch. Die nächste Verbesserung darf winzig sein.
